# 智能选品与跨境运营中台 — 产品需求文档（PRD）

> 版本：v1.1 | 状态：增强稿  
> 产品名称：华普智选（智能选品与跨境运营中台）  
> 文档目标：作为评审、研发排期与验收的统一依据；验收项按 Must / Should / Could 分级。

---

## 1. 产品定位

| 维度 | 说明 |
|------|------|
| 产品名称 | 华普智选（智能选品与跨境运营中台） |
| 目标用户 | 跨境电商卖家、运营团队（3–50 人规模）、独立选品经理 |
| 核心价值 | 数据驱动选品 + AI 自动化运营，把运营效率从人均管理 10 个 SKU 提升到 50+ 个 |
| 覆盖平台 | Amazon（主力，第一版实现）、Shopee（次选，第二版实现） |
| 交付形式 | SaaS 后端 REST API + Web 运营看板 |
| 商业模式 | 内部工具 / 可选 SaaS 订阅（后期） |
| 产品形态 | 6 个业务模块 + 8 个前端页面 |

## 2. 用户故事

### 故事 1：自动数据采集
> 作为**运营**，我希望系统自动抓取 Amazon 某个品类的商品数据（标题、价格、评分、销量排名），
> 这样我就不用每天手动翻 Amazon 搜索结果页了。

### 故事 2：市场趋势分析
> 作为**选品经理**，我希望系统按月统计品类的价格分布和增长趋势，
> 这样我就能发现哪些品类在增长、哪些在萎缩，不用靠感觉判断。

### 故事 3：AI 选品推荐
> 作为**运营主管**，我希望 AI 基于市场数据推荐「蓝海品类」——需求高但竞争少的品类，
> 这样我就能把有限的资金投在最有潜力的方向上。

### 故事 4：竞品价格监控
> 作为**运营**，我希望系统自动监控我选定商品的竞品价格变化，
> 当竞品降价超过 5% 时通知我，这样我就不会在价格战中慢半拍。

### 故事 5：AI Listing 优化
> 作为**运营**，我希望 AI 根据市场数据自动生成优化的商品标题和描述，
> 这样我就不用自己揣摩关键词怎么写了。

### 故事 6：运营看板
> 作为**老板**，我想要一个看板，一眼看到所有运营数据（品类趋势、选品进度、竞品动态），
> 这样我就不用每周让运营给我做汇报了。

## 3. MVP 功能清单（6 个模块）

### 模块一：数据接入与商品管理
自动从 Amazon（第一版）和 Shopee（第二版）拉取商品数据，建立本地商品数据库。支持品类同步、商品搜索和详情查看。

### 模块二：市场趋势分析
计算品类的价格分布、增长率、季节性，用 AI 生成可读的趋势解读报告。回答「什么东西好卖、什么品类在增长」。

### 模块三：智能选品推荐引擎
综合市场需求、竞争强度、利润空间、趋势方向四个维度打分，AI 深度分析发现蓝海品类。回答「我应该卖什么」。

### 模块四：竞品监控与预警
自动发现竞品，每小时更新竞品价格/评分，降价超阈值自动告警。回答「竞品在干什么」。

### 模块五：AI Listing 优化
基于市场数据 AI 生成优化的标题、描述和关键词，支持版本管理。回答「Listing 怎么写才能被搜到」。

### 模块六：运营看板与部署
汇总所有模块数据到一个看板，提供库存预警和销量预测。Docker 一键部署。

### 3.1 模块与页面映射

| 模块 | 主要承载页面 | 说明 |
|------|--------------|------|
| 模块一 数据接入与商品管理 | P2 商品管理、P8 数据采集配置 | 商品库消费采集结果；配置侧负责任务与品类 |
| 模块二 市场趋势分析 | P3 市场趋势 | 趋势图与 AI 解读 |
| 模块三 智能选品推荐引擎 | P4 智能选品 | 推荐列表与接受/拒绝决策 |
| 模块四 竞品监控与预警 | P5 竞品监控、P6 告警中心 | 监控绑定与告警处理分离 |
| 模块五 AI Listing 优化 | P7 Listing 优化 | 生成、双栏对比、版本采纳 |
| 模块六 运营看板与部署 | P1 运营看板 | 汇总只读视图 + 部署交付要求 |

## 4. 不做什么（明确边界）

| 功能 | 为什么不包含 | 替代方案 |
|------|-------------|---------|
| 采购管理 | 属于 ERP 范畴，本系统聚焦选品和运营 | 对接现有 ERP（预留接口） |
| 物流追踪 | 各平台自带物流系统 | 不实现 |
| 财务对账 | 涉及多平台货币换算和税务 | 建议用专业财务工具 |
| 广告投放管理 | Amazon PPC 等广告系统已有独立工具 | 不实现 |
| 社交媒体营销 | TikTok、Facebook 等属于营销范畴 | 将来可作为扩展 |
| 多语言翻译 | 不是核心能力 | AI 翻译（后续可加） |

**边界原则（MVP）：** 不做采购、不做物流、不做财务；系统止于「选什么、怎么盯竞品、怎么写 Listing、怎么看全局」。

## 6. 8 页面功能验收表

Web 运营看板共 **8 个核心页面**。优先级采用 MoSCoW：

- **Must**：MVP 上线必过，未通过不可验收  
- **Should**：强烈期望，优先排期  
- **Could**：可延后，不阻塞 MVP

| 编号 | 页面名称 | 主角色 | 对应模块 |
|------|----------|--------|----------|
| P1 | 运营看板 | 老板 | 模块六 |
| P2 | 商品管理 | 运营 | 模块一 |
| P3 | 市场趋势 | 选品经理 | 模块二 |
| P4 | 智能选品 | 选品经理 / 运营主管 | 模块三 |
| P5 | 竞品监控 | 运营 | 模块四 |
| P6 | 告警中心 | 运营 | 模块四 |
| P7 | Listing 优化 | 运营 | 模块五 |
| P8 | 数据采集配置 | 运营主管 | 模块一 / 模块六（部署相关配置入口） |

### P1 运营看板

| 优先级 | 验收项 |
|--------|--------|
| Must | 展示品类趋势摘要、选品进度（待处理 / 已接受 / 已拒绝）、竞品动态条数、未读告警数 |

### P2 商品管理

| 优先级 | 验收项 |
|--------|--------|
| Must | 列表展示标题、价格、评分、销量排名、所属品类、最近同步时间 |

|--------|--------|
| Must | 按月展示品类价格分布（区间或分位）与增长率 |

| Should | 展示季节性提示；支持品类切换与时间范围选择 |

### P4 智能选品

| 优先级 | 验收项 |

| Must | 提供「原文 / 优化稿」双栏对比视图，支持采纳为新版本 |
| Should | 版本列表可回看历史生成结果；标明生成时间与操作人 |

| 优先级 | 验收项 |

## 7. 关键交互验收

以下为跨页面验收重点，评审与测试须按路径走通；任一 Must 路径失败则对应能力不可验收。

### 7.1 选品接受 / 拒绝

| 编号 | 步骤 | 期望结果 | 级别 |
|------|------|----------|------|
| S-01 | 在 P4 打开一条「待处理」推荐 | 可见四维得分与 AI 说明 | Must |
| S-02 | 有决策权角色点击「接受」并确认 | 状态变为「已接受」；记录操作人与时间；P1 选品进度「已接受」+1 | Must |
| S-03 | 对另一条点击「拒绝」（可选填原因） | 状态变为「已拒绝」；默认待处理列表不再展示；进度统计更新 | Must |
| S-04 | 刷新页面或同权限账号再次打开 | 状态持久化，不回退为待处理 | Must |
| S-05 | 使用老板账号查看同一推荐 | 无接受 / 拒绝按钮，或按钮禁用且不可提交 | Must |

### 7.2 告警已读

| 编号 | 步骤 | 期望结果 | 级别 |
|------|------|----------|------|
| A-01 | 系统因竞品降价超过阈值产生告警 | P6 出现未读告警；P1 未读数与导航角标同步增加 | Must |
| A-02 | 在 P6 对单条点击「标记已读」 | 该条变为已读样式；未读计数 -1；角标同步 | Must |
| A-03 | 从 P5 跳转到关联告警 | 定位到对应告警条目，商品 / 竞品上下文正确 | Should |
| A-04 | 刷新后再次打开告警中心 | 已读状态保持；不重复计入未读 | Must |

### 7.3 Listing 双栏对比

| 编号 | 步骤 | 期望结果 | 级别 |
|------|------|----------|------|
| L-01 | 在 P7 选择商品并生成优化稿 | 进入双栏：左栏原文标题 / 描述 / 关键词，右栏 AI 优化稿 | Must |
| L-02 | 对照双栏内容 | 字段一一对应，可滚动阅读；生成中有明确加载态 | Must |
| L-03 | 点击「采纳为新版本」 | 写入版本历史；当前生效版本指向新稿；可再次打开历史版本 | Must |
| L-04 | 生成失败或超时 | 不展示残缺优化稿；给出可重试提示；原文不被覆盖 | Must |
| L-05 | 视口 375px 下打开双栏 | 自动上下堆叠，内容完整可读，无横向撑破 | Must（兼非功能） |

### 7.4 其他关键路径

| 编号 | 路径 | 期望结果 | 级别 |
|------|------|----------|------|
| X-01 | P1 未读告警 → P6 | 落地告警中心，并筛选未读或高亮未读 | Must |
| X-02 | P1 选品待处理 → P4 | 落地智能选品待处理列表 | Must |
| X-03 | P3 某品类趋势 → P4 | 推荐列表带上品类上下文 | Should |
| X-04 | P8 手动触发采集成功 → P2 | 商品列表可搜到更新结果，最近同步时间刷新 | Must |

## 8. 非功能需求

| 类别 | 需求 | 验收标准 |
|------|------|----------|
| 性能 | 页面加载 | 常规网络与约定数据规模下，P1–P8 核心区域可交互加载时间 **< 2s** |
| 性能 | 表格容量 | 单表在 **不少于 1000 行** 结果集下支持分页浏览；翻页与筛选不导致页面卡死 |
| 响应式 | 窄屏兼容 | 视口宽度 **375px** 下不破版：无横向撑破、主操作可点；Listing 双栏改为上下堆叠且内容完整 |
| 可用性 | 工作时段 | 工作日 9:00–22:00 可用率 > 99% |
| 数据时效 | 竞品告警 | 价格变化后告警延迟 < 30 分钟 |
| 部署 | 交付形态 | 支持 Docker 一键部署（模块六） |

### 8.1 非功能补充约定

1. **< 2s**：以预发或本地等价环境、缓存已预热（或等价条件）、千级商品数据为基准；首次冷启动的采集任务耗时不计入页面加载 SLA。  
2. **1000 行**：指单次查询结果集可分页完整遍历，**不要求**单页一次性渲染 1000 行 DOM。  
3. **375px 必测页面**：P1 运营看板、P2/P4/P6 列表、P7 Listing 双栏（堆叠态）。  
4. 性能与窄屏项纳入 MVP 验收清单，与功能 Must 同等对待。

## 9. 数据规模预估

| 指标 | 预估 |
|------|------|
| 品类数 | 50–200 个（按用户关注的品类） |
